# Inkpad Beta drawing capabilities: desktop GUI and headless MCP

This is an implementation reference for agents integrating Inkpad's **saved** drawing model. It describes source-level capabilities, not an independent assertion that every physical mouse interaction in the current GUI build has passed acceptance testing. Check `get_capabilities` and the running server's `tools/list` to discover the executable actually connected by the client. A stale Beta package may expose fewer tools.

## Where each feature is available

| Capability | Desktop GUI (current source) | MCP stdio server (current source) |
| --- | --- | --- |
| Persistent freehand ink | Pen, eraser; stroke-based canvas | `add_stroke`, atomic `add_strokes_batch` (up to 64 strokes), confirmed `undo_last_stroke`, confirmed `clear_strokes` |
| Draw new common shapes | Rectangle, ellipse, line; advanced triangle, rounded rectangle and curve tools | `drawing_create_shape`: rectangle, rounded_rectangle, ellipse, circle, line, polygon, cubic_bezier |
| Select or inspect object | Select tool, pointer hit testing and selection overlay | `drawing_list`; `drawing_pick_object` at canvas `{x,y}` with optional hit tolerance |
| Move/resize/rotate/flip selected object | Basic selection gestures and advanced controls | `drawing_transform_object` for relative move/resize/rotate/flip |
| Edit shape geometry / RGBA stroke / fill / opacity | Selected drawing tools and expandable fill/opacity controls; not every vector property exposed in GUI | `drawing_edit_shape` for full geometry, style, transform, visibility or layer association |
| Gradients | Model and renderer can display; no claim of a complete interactive gradient editor | Solid, linear and radial fill JSON with RGBA stops in `drawing_create_shape` / `drawing_edit_shape` |
| Drawing layers | Advanced "New layer" action and layer-aware renderer | Create, rename, reorder, show/hide, lock/unlock, delete empty layer |
| Object stacking | Layer-aware renderer; GUI object list/reorder remains limited | `drawing_reorder_object`; `drawing_move_layer` |
| Group shapes | No full drag/select/group interaction claimed | `drawing_group_objects`, `drawing_transform_group`, `drawing_ungroup_objects` |
| Duplicate a selected object | Advanced object action in GUI | Create a separate object; no dedicated duplicate MCP call |
| Drawing preview | Renders canvas in window | `drawing_preview` returns one `image/png` block (max 1 MiB) |
| Drawing PNG export | GUI export action | `export_note` to new absolute `.png` path, including strokes and editable vectors |
| Undo/redo drawing operations | Session-local drawing history, bounded; GUI's separate text history | Vector edit `drawing_undo` / `drawing_redo` (same active agent process only, explicit authorization and `confirm:true`) |
| Bulk or batch drawing API | GUI editing remains gesture-by-gesture | `drawing_create_scene` adds up to 512 vector objects + 16 new layers in one validated transaction; `drawing_create_batch` adds 1–64 shapes; `add_strokes_batch` paints 1–64 strokes; individual tools remain available |
| Change open GUI selection/tool/mode | User interaction in desktop window | Not supported by headless MCP |

The **default desktop editor remains simple**. Basic tools are in the drawing toolbar; further appearance and object controls are behind an expandable Advanced section. GUI checks for external changes to saved notes and may delay reloading while there are unsaved local edits. Do not assume a successful MCP write immediately changes the active visual selection.

## Persisted model and compatibility

Each `Note` retains its previous `strokes` (legacy ink), `images`, `rich_text`, body, title, and metadata. Editable shapes and layers are stored in the additional `drawing: DrawingData` field with serde defaults; old notes without it load as empty vector drawings. Existing saved strokes are **not converted** or discarded. A note can contain text, legacy strokes, inline images and editable shapes at the same time.

`drawing.layers` is an ordered array of `{id,name,visible,locked}` records (up to **64**). `drawing.objects` is an ordered array of `{id,layer_id,shape,style,transform,visible,group_id}` (up to **2000**). IDs are generated by the drawing model, and layer IDs must reference existing layers. Geometry coordinates, sizes, transforms, colours, gradient stops and style properties are validated before committing the transaction. Polygon points are limited to **256**. The drawing canvas is 1100×700 pixels.

`shape` is a tagged object with `type`: `rectangle` (`width`,`height`), `rounded_rectangle` (`width`,`height`,`radius`), `circle` (`radius`), `ellipse` (`radius_x`,`radius_y`), `line` (`to:{x,y}`), `polygon` (`points:[{x,y},...]`, optional `closed`) or `cubic_bezier` (`control1`,`control2`,`to`). Shapes live in local coordinates. A `transform` places them on the drawing with `translation:{x,y}`, `scale_x`,`scale_y`, `rotation_deg`,`flip_x`,`flip_y`.

`style` properties are optional `stroke` (RGBA array or null), `stroke_width` (0–256), `fill` (null, `{type:"solid",color:[r,g,b,a]}`, `{type:"linear_gradient",start:{x,y},end:{x,y},stops:[...]}` or `{type:"radial_gradient",center:{x,y},radius,stops:[...]}`) and `opacity` (0–1). Each gradient stop is `{offset,color:[r,g,b,a]}`, with 2–16 stops in increasing order and offsets in `[0,1]`. All RGBA channel values are integers 0–255. A missing style uses the model defaults.

Example `drawing_create_shape` `arguments`:

```json
{
  "id": "NOTE_ID",
  "shape": { "type": "rounded_rectangle", "width": 160, "height": 92, "radius": 18 },
  "transform": { "translation": { "x": 80, "y": 90 } },
  "style": {
    "stroke": [25, 30, 40, 255], "stroke_width": 3, "opacity": 1,
    "fill": { "type": "linear_gradient", "start": { "x": 0, "y": 0 }, "end": { "x": 160, "y": 92 },
      "stops": [ { "offset": 0, "color": [255, 223, 91, 255] },
                 { "offset": 1, "color": [245, 125, 80, 255] } ] }
  }
}
```

The response supplies `object.id`; obtain all IDs with `drawing_list` if needed. To move it 30 pixels right, call `drawing_transform_object` with `{"id":"NOTE_ID","object_id":"RETURNED_OBJECT_ID","operation":"move","dx":30,"dy":0}`. For `drawing_transform_group`, supply `group_id` instead of `object_id` and the same transform operation arguments. A group is membership metadata; objects keep their independent geometries. To inspect a point use `drawing_pick_object` with `x`, `y` and optional `tolerance` from 0 to 32 pixels. It ignores hidden and locked shapes by design.

## Safety and undo semantics

The MCP process performs each editing tool call through `Store::mutate` under the workspace's cross-process file lock. Invalid shapes, unknown arguments, missing IDs, locked target layers and out-of-bounds geometry cause an error, without writing a partial note. Edits preserve the unrelated text, legacy strokes and image references.

`drawing_delete_object` and `drawing_delete_layer` require the user to actually authorize removal and the caller to provide `confirm:true`. A layer can only be removed when empty and unlocked. Undo and redo can restore or remove shapes, so `drawing_undo` and `drawing_redo` also require explicit authorization and `confirm:true`. The extra flags do **not** prove user consent; calling agents must determine authorization from the user's request.

MCP drawing history is maintained in the lifetime of the connected agent process (48 saved vector snapshots per note); it is **not** a durable history in `workspace.json`. After a restart, no MCP undo history is available. The agent compares the last expected drawing with a fresh on-disk snapshot before each undo/redo, and refuses if the GUI or another agent has changed it. `undo_last_stroke` remains a separate confirmed legacy-stroke action; rich-text undo history is likewise independent and transient. Undo/redo actions only apply to the vector layer, never the note's text, attachments, or legacy ink.

`drawing_preview` streams a standard MCP PNG image block (1100×700, up to 1 MiB compressed) and no file is written. `export_note` with `format:"png"` writes the complete saved drawing to a **new** absolute PNG path and rejects overwrite. Neither method renders the note's body text into the drawing PNG. `image_export_html` is the separate self-contained note export, which can include text, drawings and inline attached images. Do not use either export to upload private notebook contents to a network service without the user's request.

## Verification boundary

These capabilities are verified at the Rust model/MCP source and unit-test layer. The GUI drawing toolbar, selection, alignment, themes and responsiveness still require a physical mouse/keyboard screenshot review on a real window before any numerical quality rating. Never claim that a tested model operation proves the corresponding GUI hit target or button works. Conversely, do not hide supported headless capabilities simply because the GUI does not yet expose their full controls.
