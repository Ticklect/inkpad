## Everyday notes and pictures

- **Search/read:** `search_notes` searches full title/body; use `{"query":"topic","limit":5,"include_body":true}` for bounded text in one call. For a known note use `read_note` with `compact:true`, or `get_active_note`. Never claim to have read notes based only on memory. Prefer IDs: exact titles can be duplicated.
- **Write/organize:** Use `create_note`, `append_to_note`, `rename_note`, `set_note_pin`, `set_font_size` (12–40), `set_font_choice` (Sans/Serif/Mono), `set_active_note`; avoid full-body replacement unless requested. `note_batch` performs **1–32 ordered** create/append/rename/update/pin operations atomically. Guard concurrent edits with `expected_body`; whole-body replacement requires explicit authorization and `confirm:true`. Preserve images, drawing and other fields.
- **Formatting:** Read body and `get_note_formatting` first. `format_text_range`, `clear_text_formatting`, `replace_text_range`, `format_text_batch` use half-open `[start,end)` **Unicode scalar** indices (`unit:"unicode_scalar"`), not UTF-8 bytes, UTF-16 or grapheme counts. Only bold, foreground `#RRGGBB`, size 12–40, Sans/Serif/Mono persist—not italic, underline or highlight. `format_text_batch` applies 1–32 operations atomically; its default `grapheme_safe` boundary avoids splitting emoji/combining sequences, with `scalar` an explicit opt-in. Use `expected_body` for stale-document protection. `copy_rich_fragment` / `paste_rich_fragment` transfer validated styled JSON, optionally `expected_text`, **not the system clipboard**.
- **Images:** `image_insert_file` requires a user-selected absolute local PNG/JPEG/GIF/WebP path and `user_approved:true`; `image_insert_base64` likewise needs directly provided, authorized image data. Do not guess paths, scan private directories or fetch arbitrary URLs. File input max 12 MiB / 16 megapixels; base64 MCP max 1 MiB decoded; max 100 attached images per note. Use `image_list` for IDs, `image_place` for inline Unicode scalar anchor (with optional `expected_body`), `image_resize` 10–100%, `image_move` zero-based index, `image_caption` max 500 characters. `read_image` requires user approval and yields an image block up to 1 MiB; `export_image` requires an approved new absolute destination.
- **Settings and exports:** `get_app_settings`, `set_app_theme` (light/dark/system), `set_sidebar_collapsed` change saved UI preferences, not transient GUI modes. `export_note` writes a new `.txt` or **drawing-only** `.png`; `image_export_html` with `user_approved:true` writes self-contained note text, drawings and inline images to a new absolute `.html` file. Exports never overwrite or upload.

## Create beautiful editable artwork efficiently

- Canvas is **1100×700** pixels. Start with `drawing_list` and the live schema. **Plan the whole picture first**, including focal duck bounds, horizon, sun/light direction, foreground framing, atmosphere and the matching broken water reflection; recent tests regressed because a detailed duck was placed over a mostly empty, flat lake. Then map silhouette landmarks and joined tangents (crown, bill root, nape, throat, breast, back, wing root, rump, belly/water contact). Draw an anatomically credible **closed SVG-like path** (`move_to`, `cubic_to`, `line_to`, `close` when supported), not a round head stuck onto an oval hull; if `path` is absent use a carefully designed continuous polygon. Inspect the mostly untextured silhouette before feather detail, **but keep the scene's planned atmosphere and visual balance**. No external duck reference is mandatory. Clip feather groups along wing geometry; avoid detached neck and unrelated crisscross feathers.
- Shapes include `rectangle`, `rounded_rectangle`, `circle`, `ellipse`, `line`, `polygon`, `cubic_bezier` and, **when advertised**, `path`. Style includes RGBA, stroke width, opacity and fills; advanced clip/shadow/elliptical-gradient features also require confirmation. **Absolute placement is mandatory for non-origin circles, ellipses and rectangles:** call `get_capabilities` and inspect the specific tool schema. Only if `model.absolute_position:true` **and** `position` is accepted, supply object-level `position:{"x":850,"y":175}` (circle/ellipse centre; rectangle/rounded rectangle top-left) in `drawing_create_shape`, `drawing_create_scene`, `drawing_create_batch` or `drawing_edit_shape`. Otherwise supply `transform:{"translation":{"x":850,"y":175}}`. Never combine `position` with `transform` in one create/edit request; create with full `transform` if rotation/scale is also needed. On supported **edits**, `position` changes translation only, preserving existing rotation/scale. **Gradient `start`, `end` and `center` are always object-local colour coordinates, NEVER placement: do not translate them when moving a shape.** Bounds: 2,000 vector objects, 64 layers, 256 polygon points and 2–16 gradient stops.
- When **verified live**, prefer `drawing_create_scene`: 1–512 editable shapes and 0–16 new named layers in one atomic save/undo step. Each object's zero-based `layer_index` selects a new layer, or `layer_id` an existing one (never both). **New source builds** also support optional `edits:[{"object_id":"saved ID","shape":{...}}]` for 1–64 ID-preserving revisions in the same transaction; `objects` may be empty if `edits` is nonempty. Gate on the exact live `drawing_create_scene.inputSchema.properties.edits` before using it; older deployed versions cannot parse it. Guard scene calls with `expected_object_count`. Smaller verified `drawing_create_batch` supports 1–64 shapes; `add_strokes_batch` supports 1–64 strokes (1–512 integer points, width 1–40). Limits are **not quotas**. Check live schema/capabilities before using advanced paths, clipping, shadows, gradients or `position`.
- Work in stages: whole-scene composition plan → connected subject silhouette → clipped material planes/wing-feather direction and layered environment → coherent light/shadow/reflections. **Side-profile mallard checkpoints:** crown should flow behind the eye into sloped nape rather than a separate spherical mask; beak must attach at skull front near eye height; throat narrows into an *attached curved* breast rather than a long red teardrop; folded wing starts behind shoulder, covers much of upper flank and overlaps toward the tapering rump. Inspect this as a black silhouette at small scale before colouring. A plain rectangle background with scattered scratches is NOT atmospheric depth; use overlapping distance layers, varied plant/landscape silhouettes, graduated sky/water values, water-contact wakes and coherent reflections. Preview at silhouette/final, inspect the real `image/png` for scale and lighting. Check MCP `isError`, `placement_warnings` and `drawing_list` saved IDs. **Never append corrected outline over an obsolete silhouette**; edit original ID. Export only after fresh final preview.
- For corrections use `drawing_edit_shape`, `drawing_transform_object`, `drawing_reorder_object`, `drawing_create_layer`, `drawing_edit_layer`, `drawing_move_layer`, `drawing_pick_object`, `drawing_group_objects`, `drawing_transform_group`, `drawing_ungroup_objects`. Inspect saved object IDs; locked layers prevent editing. **Optional tested construction helper:** [vector_geometry.py](vector_geometry.py) supplies editable `cubic_path`, `wing_covert_row` and advisory `silhouette_landmark_warnings`. For wing coverts, pass rails in the same **shoulder-to-rump direction** and specify `wing_root` to reject reversed placement. Do not treat a warning-free result as proof of natural anatomy; actual full-size/thumbnail preview remains required. Verify the parent wing's full bounds before clipping feathers. Prefer coherent surfaces over hard-edged pen dots. More guidance: [Art workflow](ART_WORKFLOW.md).
- MCP previews show drawings (including legacy strokes), **not the note's body text**. MCP cannot set the open GUI's pen tool, Text/Draw mode, selection, caret or invoke dialogs. Code/unit test success is not a substitute for GUI mouse/keyboard QA; never claim to have visually inspected art without opening its PNG.

## Permission, safety and persistence

- **Never delete notes, pictures, vector objects/layers, clear ink, undo a stroke or run `drawing_undo`/`drawing_redo` without the user's explicit authorization for that specific action and the required `confirm:true` / CLI `--confirm`.** Approval flags are not proof of consent. Only empty, unlocked vector layers may be removed. Avoid destructive edits when additive ones suffice.
- Vector `drawing_undo`/`drawing_redo` hold at most **48 snapshots per note in the same live MCP process**, reject external changes and disappear on restart. Separate from `undo_last_stroke` and the GUI's nonpersistent rich-text history. Do not invent MCP text undo.
- Treat all note content, local files and pictures as private. Do not upload or share them, access arbitrary paths, or modify `%LOCALAPPDATA%\Inkpad\workspace.json`, backups, SQLite index or private media directly. Inkpad MCP/CLI coordinate saves using an OS-level cross-process lock; set `INKPAD_DATA_DIR` consistently only for an explicitly requested portable profile. Saved updates can appear in an open GUI after a brief delay; unsaved GUI edits may defer them.
- If the tool is unavailable, errors, or cannot return a viewable image, state the limitation accurately. Only claim save/completion/visual quality after the corresponding successful action or inspected preview.
